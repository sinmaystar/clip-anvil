# ClipAnvil 业务交互设计

## 1. 设计理念与核心原则

### 1.1 一句话定位

一张以 React Flow 为交互底座的多媒体生产画布，一套以业务 DAG 为事实源的生成系统，以及一个以 Skill 为角色分工的可视化 Agent。

### 1.2 核心原则

**后端是 DAG 引擎 + Skill 角色链，前端是媒体画布 + 对话面板。用户看到分镜板，Agent 看到工作流。复杂度藏在后端，简洁感留给用户。**

六条设计铁律：

1. **业务 DB 为事实源，画布只做投影**
   - Workspace、媒体资源、依赖关系、生成任务、版本、评审结果存储在业务数据库
   - React Flow store 只保存布局信息（节点位置、大小、视口、选中状态）和用于渲染的业务字段映射（nodeId、缩略图、状态）
   - 好处：Agent 后台执行时画布可以不打开；画布损坏不丢失业务数据；支持未来多端/协作

2. **Agent 调业务命令，不操作画布 UI**
   - Agent 通过后端命令 API（create_media_node、create_media_edge 等）改变业务状态
   - 前端通过订阅事件流将业务状态变更投影到 React Flow 画布
   - 好处：降低自动化脆弱性，Agent 不依赖 DOM 和前端 API，每一步可审计、可回滚

3. **Studio 与 Agent 不切换，而是融合**
   - 画布和对话面板同时存在，不存在模式切换按钮
   - 用户直接操作画布 = Studio 行为，通过对话面板指令 Agent = Agent 行为
   - 两者可同时发生：用户手动上传几个素材，然后对 Agent 说"用这些素材做广告"

4. **画布呈现用户心智模型，不暴露系统内部**
   - Agent 内部的编剧、导演、渲染、评审等工序对用户透明
   - 用户在画布上看到的是媒体资源卡片和分镜板，不是 DAG 工作流图
   - Brief 节点、Production Plan 节点、VFX Review 节点等系统节点不出现在画布上

5. **不弹框，不打断画布流**
   - 简单编辑在节点卡片上内联完成
   - 深度编辑在右侧属性面板展开
   - 全程无 Modal Dialog

6. **交互强度自适应，不要求用户预选**
   - 不设"自动驾驶 / 带确认 / 协作"三档模式选择
   - Agent 默认在关键节点自动暂停等待确认（Gate）
   - 用户点击任何节点编辑 → 该节点自动进入 UserEditing 状态，Agent 暂停该分支
   - 用户在对话框说"停一下" → Agent 全局暂停
   - 用户行为本身就是意图的表达，系统自适应响应

## 2. 信息架构与数据模型

### 2.1 双层架构

```
用户 / Agent
     │
     ▼
业务命令 API ──→ 业务数据库（事实源）──→ 实时事件流 ──→ React Flow 画布投影
     │
     ▼
生成任务队列 ──→ 模型供应商 / 渲染器 ──→ 业务数据库
```

- **业务层**：定义 Workspace 中真实存在的媒体资源、生成任务和血缘关系
- **画布层**：将业务对象投影为 React Flow 上的位置、大小、折叠状态和视觉样式

### 2.2 核心实体

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **Workspace** | id, name, owner, settings | 顶层组织单位，对应一个项目 |
| **CanvasDocument** | id, workspaceId, React FlowSnapshot, layoutVersion | 画布布局和 UI 投影，不承载业务事实 |
| **MediaAsset** | id, type, mime, storageUrl, thumbnailUrl, duration, size | 文件级资产（图片、视频、音频、文本内容），存储在 MinIO |
| **MediaNode** | id, workspaceId, assetId, nodeType, title, status, prompt, modelProvider, currentVersionId | 画布上的业务节点，React Flow node 通过 nodeId 映射 |
| **MediaGroup** | id, workspaceId, name, parentId, nodeIds | 视觉/组织分组，对应左侧资源树和画布 group node |
| **MediaEdge** | id, fromNodeId, toNodeId, edgeType, transition | 节点间关系，edgeType 见 2.3 |
| **GenerationJob** | id, targetNodeId, provider, model, prompt, params, status, cost | 一次生成或处理任务 |
| **ArtifactVersion** | id, nodeId, jobId, assetId, versionNo, winner, reviewScore, inputHash | 节点产物版本，支持多候选和重试 |
| **ReviewRecord** | id, versionId, axes, score, critique, verdict | 自动或人工评审结果 |
| **AgentStep** | id, workspaceId, stepType, input, output, createdNodes | Agent 操作审计日志 |

### 2.3 三种连线语义（MediaEdge.edgeType）

连线按**语义**分类，不按创建方式分类。创建来源（用户手动 / @引用 / Agent 自动）记录在 edge 的 metadata 中。

| edgeType | 视觉样式 | 语义 | 示例 |
|---|---|---|---|
| `dependency` | 蓝色实线 + 箭头 | A 的输出作为 B 的输入，B 依赖 A | 产品图 → 视频节点 |
| `reference` | 紫色虚线 | A 作为 B 的风格/内容参考，非强依赖 | 竞品广告 → 自己的视频 |
| `sequence` | 绿色实线 | A 在成片中排在 B 前面，定义时间线顺序 | 镜头01 → 镜头02 |

sequence 类型的 edge 额外携带 `transition` 字段：

```
transition: {
  type: 'cut' | 'crossfade' | 'dissolve' | 'wipe',
  duration: number  // 秒
}
```

### 2.4 节点状态机（MediaNode.status）

```
Draft ──→ Ready ──→ Queued ──→ Running ──→ Succeeded
  ↑                                           │
  │         UserEditing ◄── 用户点击编辑       │
  │              │                             │
  │              ▼                             ▼
  └──── Stale ◄──────────────────────── 上游变更传播
                                               │
                                         Failed / Rejected
```

| 状态 | 含义 | 画布视觉 |
|---|---|---|
| Draft | 空白节点，未填入内容 | 虚线边框 |
| Ready | 内容就绪，可以提交生成 | 灰色实线 |
| Queued | 已排队等待生成 | 灰色实线 + ⏳ |
| Running | 正在生成 | 蓝色边框 + 光晕 + 进度条 |
| Succeeded | 生成完成且通过评审 | 绿色边框 + 评分 |
| Failed | 生成失败或评审不通过 | 红色边框 |
| Stale | 上游依赖已变更，当前产物过期 | 黄色虚线边框 |
| UserEditing | 用户正在手动编辑，Agent 暂停该分支 | 橙色边框 |

### 2.5 React Flow node 与业务实体的映射

React Flow node data 只保存渲染所需的最小字段：

```typescript
interface MediaFlowNodeProps {
  nodeId: string          // 关联 MediaNode.id
  nodeType: MediaType     // text | image | video | audio
  title: string           // 显示标题
  status: NodeStatus      // 用于渲染边框颜色和状态图标
  thumbnailUrl?: string   // 缩略图 URL
  progress?: number       // 生成进度 0-100
  reviewScore?: number    // 评审分数
  isAgentCreated: boolean // 是否 Agent 创建（蓝色虚线 vs 实线）
}
```

完整的 Prompt、模型参数、版本历史、评审详情等通过 nodeId 从业务 API 按需加载，不存入 node data。

## 3. 主界面布局

### 3.1 三栏融合布局

```
┌──────────────────────────────────────────────────────────────┐
│  影砧  |  ☕ 咖啡广告项目 · 已保存          ⌘K   导出  设置  │
├──────────┬─────────────────────────────┬─────────────────────┤
│          │                             │  💬 对话  |  ⚙ 属性 │
│  资源    │                             │                     │
│          │      浮动工具栏              │  [对话消息]          │
│  🔍搜索   │  [选择|文本|图片|视频|音频]   │                     │
│          │                             │  [Agent 状态]        │
│ [类型筛选]│                             │                     │
│          │        画布区域              │                     │
│  📁 角色  │    （React Flow 无限画布）       │                     │
│   🖼 ...  │                             │                     │
│  📁 分镜  │     [媒体节点卡片]           │                     │
│   🎬 ...  │     [连线 / 箭头]           │                     │
│  📁 音频  │     [分组容器]              │                     │
│   🔊 ...  │                             │  [输入框]            │
│          │  [缩放控件]                  │  [@ 引用] [上传] [暂停]│
└──────────┴─────────────────────────────┴─────────────────────┘
 ~200px            flex:1                     ~280px
```

### 3.2 三栏职责

| 区域 | 职责 | 交互 |
|---|---|---|
| **左侧资源树** | Workspace 内所有媒体资源的索引和组织 | 搜索、类型筛选（全部/图片/视频/文本/音频）、文件夹层级、拖拽到画布、状态徽标（✓/⟳/○） |
| **中间画布** | React Flow 无限画布，承载媒体节点卡片、连线、分组 | 平移/缩放、右键创建、拖拽连线、选中节点、浮动工具栏 |
| **右侧面板** | 对话 Tab + 属性 Tab | 对话 Tab：与 Agent 交互、查看进度；属性 Tab：选中节点的详细属性编辑 |

### 3.3 面板联动规则

- 未选中任何节点时：右侧默认显示对话 Tab
- 单击选中一个节点时：右侧自动切到属性 Tab，展示该节点详情
- 点击画布空白区域取消选择：右侧切回对话 Tab
- 左侧资源树点击某资源：画布定位到对应节点 + 右侧展示属性
- Agent 创建新节点时：如果用户当前在对话 Tab，保持不切换；画布自动平移到新节点区域

### 3.4 左侧资源树设计

一棵树 + 筛选，不搞多视图切换：

- **顶部搜索框**：按名称模糊搜索
- **类型筛选 chips**：全部 / 图片 / 视频 / 文本 / 音频，单选切换
- **树结构**：文件夹（MediaGroup）+ 资源（MediaNode），支持拖拽排序和嵌套
- **状态徽标**：每个资源右侧显示状态图标（✓ 完成 / ⟳ 生成中 / ○ 草稿 / ⚠ 过期 / ✗ 失败）
- **底部折叠按钮**：可收起侧栏以获得更大画布空间

### 3.5 浮动工具栏

画布顶部居中的浮动工具栏，提供快捷创建入口：

```
[ ↖选择 | 📝文本 | 🖼图片 | 🎬视频 | 🔊音频 | — | 📎上传 ]
```

选择工具类型后，在画布上点击即创建对应类型的 Draft 节点。

## 4. 画布原子能力（Studio / Agent 共享层）

### 4.1 共享命令 API

Studio 和 Agent 的区别只在入口层。两者共享同一套业务命令，每个命令包含参数校验、权限检查、DB 写入、事件广播和审计日志。

| 命令 | 用途 | Studio 触发方式 | Agent 触发方式 |
|---|---|---|---|
| `create_media_node` | 创建媒体节点 | 右键菜单 / 工具栏点击 | Agent 规划分镜时批量调用 |
| `update_media_node` | 更新节点内容、Prompt、参数、状态 | 内联编辑 / 属性面板修改 | Agent 填充生成结果 |
| `delete_media_node` | 删除节点 | 选中后按 Delete | Agent 重新规划时清理 |
| `create_media_edge` | 建立节点间关系 | 拖拽连线 / Prompt 中 @引用 | Agent 自动建立依赖 |
| `delete_media_edge` | 删除连线 | 选中连线后删除 | Agent 重新规划时调整 |
| `create_group` | 创建分组 | 选中多个节点后右键分组 | Agent 按场景/阶段自动分组 |
| `submit_generation` | 提交生成任务 | 节点上点击"生成"按钮 | Agent 按 DAG 拓扑序自动提交 |
| `promote_version` | 将某版本设为 winner | 版本列表中点击"选择" | Agent 根据评审分数自动选择 |
| `mark_stale` | 标记节点及下游过期 | 修改上游节点后自动触发 | 同左 |
| `request_gate` | 请求用户确认 | 不适用 | Agent 在关键阶段调用 |

### 4.2 事件流与画布同步

业务命令执行后广播事件，前端订阅事件更新画布：

```
命令执行 → DB 写入 → 广播事件 → 前端收到事件 → 更新 React Flow store → 画布刷新
```

关键事件类型：

| 事件 | 画布响应 |
|---|---|
| `NodeCreated` | 创建对应类型的 React Flow node，自动布局 |
| `NodeUpdated` | 更新 node data（状态、缩略图、进度等） |
| `NodeDeleted` | 删除 node |
| `EdgeCreated` | 创建 custom edge + edge |
| `EdgeDeleted` | 删除 custom edge + edge |
| `JobProgress` | 更新节点进度条 |
| `JobCompleted` | 更新节点状态为 Succeeded，刷新缩略图 |
| `JobFailed` | 更新节点状态为 Failed |
| `GateRequested` | 在对话面板展示确认请求 |

### 4.3 乐观更新

Studio 模式下用户直接操作画布时，必须保证即时反馈：

1. 用户操作 → **立即**更新 React Flow store（node 出现在画布上）
2. 同时异步调用业务命令 API
3. 成功 → 无感知（已经渲染了）
4. 失败 → 回滚 node，提示错误

这是 Google Docs / Figma 的标准做法，确保 Studio 模式下的画布操作没有延迟感。

Agent 模式下无需乐观更新——Agent 操作经由事件流推送，用户对几百毫秒延迟无感知。

## 5. Studio 模式交互设计

### 5.1 定位

Studio 是用户主导的自由创作空间。用户可以像使用白板一样组织素材，也可以像使用节点编辑器一样把媒体资源连成生成流程。Studio 不是一个独立模式，而是用户直接操作画布时的行为集合。

### 5.2 创建资源

四种创建入口：

| 入口 | 操作 | 适用场景 |
|---|---|---|
| **右键菜单** | 画布空白处右键 → 选择类型（文本/图片/视频/音频/上传/分组） | 精确定位创建 |
| **浮动工具栏** | 选择工具类型 → 画布上点击 | 批量创建同类节点 |
| **拖拽上传** | 从系统文件管理器拖文件到画布 | 快速导入本地素材 |
| **左侧资源树** | 点击 + 按钮新建 | 先建资源，稍后拖到画布 |

创建后生成一个 Draft 状态的 MediaNode + 空白 MediaAsset，画布上出现对应类型的占位卡片。

### 5.3 编辑资源：内联 + 侧面板双层

| 编辑深度 | 交互方式 | 覆盖内容 |
|---|---|---|
| **轻量编辑** | 直接在节点卡片上操作 | 修改标题、编写 Prompt、选择模型、点击生成 |
| **深度编辑** | 单击节点 → 右侧属性面板展开 | 版本历史、模型参数调节、评审记录、高级选项、参考输入管理 |

内联编辑的节点卡片结构：

```
┌──────────────────────┐
│ 🎬 标题        [状态] │  ← 头部：类型图标 + 标题 + 状态
├──────────────────────┤
│ [缩略图/预览/占位]    │  ← 内容区：根据类型渲染
├──────────────────────┤
│ 输入引用: @A @B       │  ← 输入引用列表
├──────────────────────┤
│ [Prompt 输入区域]     │  ← 可直接编写，支持 @引用
│ [模型选择 ▾] [▶生成]  │  ← 操作按钮
└──────────────────────┘
  ●                   ●   ← 左侧输入端口 / 右侧输出端口
```

### 5.4 建立连线

三种连线方式：

1. **拖拽连线**：从节点 A 的输出端口（右侧圆点）拖到节点 B 的输入端口（左侧圆点）→ 创建 dependency edge
2. **Prompt @引用**：在 B 的 Prompt 中输入 `@` 弹出资源选择器 → 选择 A → 自动创建 dependency edge + 在 Prompt 中插入引用标记
3. **Agent 自动**：Agent 根据语义自动建立连线，edge metadata 标记 `source: 'agent'`

连线创建后，B 的"输入引用"区域自动展示 A 的缩略图和标题。

### 5.5 分组操作

- **创建分组**：选中多个节点 → 右键"创建分组" / ⌘G → 节点被包裹在虚线容器中
- **拖入/拖出分组**：直接拖拽节点进出分组容器
- **折叠分组**：点击分组标题栏可折叠，只显示分组名称和成员计数
- **左侧同步**：分组变更实时同步到资源树的文件夹层级

分组是纯视觉/组织工具，依赖（MediaEdge）可以自由跨越分组边界。

### 5.6 生成流程

1. 用户在节点卡片上编写 Prompt、选择模型供应商
2. 点击"▶ 生成" → 调用 `submit_generation` → 节点状态从 Ready → Queued → Running
3. 进度通过事件流实时推送 → 卡片显示进度条
4. 生成完成 → 自动评审 → Succeeded（绿色）或 Failed（红色）
5. 用户可在属性面板查看版本列表、切换 winner、请求重新生成

## 6. Agent 模式交互设计

### 6.1 定位

Agent 模式的定位是"默认由 Agent 主导生产，用户在关键节点确认、随时可局部接管"。Agent 不是一个从 Prompt 到视频的黑盒按钮，而是一个可视化的、可追溯的、可干预的自动化生产流程。

### 6.2 完整用户动线

```
输入需求 → Agent 规划分镜 → Gate:确认分镜 → 逐镜头生成（实时更新）
    → 可随时干预 → 自动拼接 → Gate:预览成片 → 导出
```

#### Step 1：用户输入需求

用户在右侧对话面板输入自然语言描述，可附带上传素材（图片、参考视频、音频）。

示例输入：*"帮我做一个30秒的咖啡新品广告，目标抖音投放，风格时尚简约。产品是燕麦拿铁，卖点是低糖健康。"*

#### Step 2：Agent 规划分镜 → 画布出现分镜卡片

Agent 内部经过需求解析、资产规划、剧本和分镜生成（这些工序对用户透明），在画布上实时创建分镜卡片。用户看到的是一排分镜卡片逐步出现：

```
┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
│ 01 产品  │ │ 02 场景  │ │ 03 卖点  │ │ 04 情感  │ │ 05 品牌  │
│ 特写 3s  │ │ 展示 8s  │ │ 展示 6s  │ │ 共鸣 8s  │ │ 收尾 5s  │
└─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘
                    总时长 30s · 5 镜头
```

同时，Agent 自动创建素材节点（角色参考图、产品图、BGM 等）并建立与分镜卡片的连线。

画布顶部显示 Agent 状态栏：
```
🔵 Agent 已规划 5 个分镜，等待确认...                    [⏸ 暂停]
```

#### Step 3：Gate 1 — 分镜确认

Agent 在对话面板请求确认：*"分镜规划好了，共 5 个镜头，总时长 30s。确认开始生成吗？"*

用户可以：
- ✅ 确认 → Agent 开始按拓扑序执行生成
- 💬 对话修改 → *"第三个镜头改成倒咖啡的过程"* → Agent 更新分镜
- 🖱 直接点击卡片编辑 → 节点进入 UserEditing → 手动调整后交还 Agent

#### Step 4：逐镜头生成，画布实时更新

Agent 按依赖拓扑序逐个生成。每个镜头经历 Queued → Running → Succeeded/Failed：

- 完成的卡片：绿色边框 + 缩略图 + 评分
- 生成中的卡片：蓝色边框 + 光晕 + 进度条
- 等待中的卡片：灰色半透明

如果某镜头评审不通过，Agent 自动改写 Prompt 重试（最多 3 次）。3 次都失败则在对话面板请求用户帮助，并给出建议。

#### Step 5：用户随时干预

生成过程中用户可以：

| 干预方式 | 系统响应 |
|---|---|
| 点击某个分镜卡片 | 右侧切到属性面板，节点进入 UserEditing，Agent 暂停该分支但继续其他分支 |
| 在对话面板说"停一下" | Agent 全局暂停 |
| 在对话面板说"第二个镜头换成户外场景" | Agent 更新该镜头 + 标记下游 Stale |
| 编辑完点击"交还 Agent" | 节点退出 UserEditing，Agent 恢复该分支自动化 |

#### Step 6：自动拼接 + Gate 2 — 成片预览

所有镜头都有 winner 后，Agent 自动拼接：添加转场、BGM、字幕。画布切换为预览模式，显示视频播放器 + 时间线：

```
┌─────────────────────────────────────────┐
│              [▶ 播放预览]                │
├─────────────────────────────────────────┤
│ [01 特写][  02 使用场景  ][ 03 卖点 ][  04 情感  ][05品牌]│
│  0:00                                       0:30 │
└─────────────────────────────────────────┘
  [ ✓导出 ] [ 调整分镜 ] [ 添加BGM ] [ 添加字幕 ]
```

用户点击时间线上的某段 → 定位到源分镜卡片 → 可修改后只重新生成该镜头 → 增量重拼接。

### 6.3 Agent 创建节点的视觉区分

Agent 创建的节点使用蓝色虚线边框，用户手动创建的使用实线边框。让用户清楚知道哪些是 Agent 做的，便于审核和信任建立。

### 6.4 模式融合场景

用户不需要在 Studio 和 Agent 之间"切换"。典型融合场景：

1. 用户在画布上手动上传了产品图、Logo、BGM
2. 在对话面板说"用这些素材做一个 15 秒广告"
3. Agent 识别画布上现有的 3 个素材节点，在此基础上补全分镜
4. Agent 创建的节点（蓝色虚线边框）自动连线到用户的素材节点（实线边框）
5. 用户可以随时在画布上手动调整任何节点，不论是自己创建的还是 Agent 创建的

## 7. 节点、连线与分组视觉设计

### 7.1 四种媒体节点

所有节点共享统一的卡片结构，通过类型图标、内容区渲染方式和端口配置区分。

| nodeType | 类型图标 | 内容区渲染 | 典型尺寸 |
|---|---|---|---|
| `text` | 📝 | 文本摘要预览（前 3 行），溢出截断 | 200×120 |
| `image` | 🖼 | 缩略图填充，点击可放大 | 200×160 |
| `video` | 🎬 | 缩略图 + 时长标签 + ▶ 播放按钮 | 240×180 |
| `audio` | 🔊 | 波形图预览 + 时长标签 | 200×80 |

### 7.2 节点卡片视觉规格

```
┌─────────────────────────┐
│ [图标] 标题       [状态] │  ← 头部 32px：类型图标 + 可编辑标题 + 状态色块
├─────────────────────────┤
│                         │
│    [内容预览区域]        │  ← 内容区：按 nodeType 渲染
│                         │
├─────────────────────────┤
│ 输入: @素材A @素材B      │  ← 引用条 20px：上游依赖的缩略 chip
├─────────────────────────┤
│ [Prompt]    [模型▾][▶]  │  ← 操作栏 32px：Prompt 单行预览 + 模型 + 生成
└─────────────────────────┘
● 输入端口（左中）    输出端口（右中） ●
```

**边框样式随状态变化**（对应 2.4 节状态机）：

| 状态 | 边框 | 额外视觉 |
|---|---|---|
| Draft | 1px 灰色虚线 | 内容区显示占位提示 |
| Ready | 1px 灰色实线 | — |
| Queued | 1px 灰色实线 | 右上角 ⏳ 图标 |
| Running | 2px 蓝色实线 | 外发光 + 底部进度条 |
| Succeeded | 2px 绿色实线 | 左下角评分徽标 |
| Failed | 2px 红色实线 | 右上角 ✗ + 失败原因 tooltip |
| Stale | 2px 黄色虚线 | 右上角 ⚠ + 黄色半透明遮罩 |
| UserEditing | 2px 橙色实线 | 右上角 ✎ + "编辑中" 标签 |

**Agent 创建 vs 用户创建**：

- 用户创建：实线边框
- Agent 创建：虚线边框 + 蓝色色调
- 两者在交互能力上完全一致，视觉区分仅用于信任透明

### 7.3 连线视觉规格

三种 edgeType 的视觉映射：

| edgeType | 线型 | 颜色 | 箭头 | 标签 |
|---|---|---|---|---|
| `dependency` | 2px 实线 | `#3b82f6` 蓝 | 实心三角 | 无 |
| `reference` | 2px 虚线 | `#a855f7` 紫 | 空心三角 | "参考" |
| `sequence` | 2px 实线 | `#22c55e` 绿 | 实心三角 | 转场类型 + 时长 |

**连线端口规则**：

- 每个节点左侧中点为输入端口，右侧中点为输出端口
- 端口在鼠标悬停节点时显示为实心圆点（半径 4px）
- 拖拽端口时高亮所有合法目标端口
- 禁止自连接和环形依赖（前端校验 + 后端二次校验）

**连线选中交互**：

- 点击连线 → 选中高亮（线宽变 3px）
- 选中 dependency/reference edge → 右侧属性面板显示连线详情
- 选中 sequence edge → 右侧属性面板显示转场配置（类型选择 + 时长滑块）
- 画布上 sequence edge 的标签可点击，弹出转场快捷配置浮层

### 7.4 分组视觉规格

分组使用 React Flow 的 GroupFlowNode，视觉表现为虚线容器：

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  📁 广告分镜 (4)    [▼折叠]     ← 标题栏：名称 + 成员计数 + 折叠按钮
├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
│                              │
│  [节点A]  [节点B]  [节点C]    │  ← 内部节点自由布局
│           [节点D]             │
│                              │
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

**折叠态**：

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  📁 广告分镜 (4)   [▶展开]   ← 折叠后只显示标题栏
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

**分组行为规则**：

- 分组是纯组织工具，不影响依赖关系和生成逻辑
- 依赖连线可以自由跨越分组边界
- 拖拽节点进入分组容器 → 自动加入分组
- 拖拽节点移出分组容器 → 自动脱离分组
- 移动分组 → 内部节点跟随移动
- 删除分组 → 内部节点保留，仅解除分组关系
- 分组可嵌套（支持 parentId），但建议不超过 2 层
- 画布分组与左侧资源树文件夹双向同步

## 8. 关键机制

### 8.1 版本管理与 Winner 机制

每次生成产生一个 ArtifactVersion，一个节点可以有多个版本。`winner` 标记当前选中的版本。

**版本生命周期**：

1. 用户/Agent 调用 `submit_generation` → 创建 GenerationJob → 生成完成后创建 ArtifactVersion
2. 自动评审（ReviewRecord）给出分数和维度评价
3. 如果分数达标，自动 `promote_version` 设为 winner
4. 如果分数不达标且 Agent 模式，Agent 修改 Prompt 重试（最多 3 次）
5. 用户可在属性面板查看所有版本，手动切换 winner

**版本列表交互（属性面板）**：

- 网格布局展示所有版本的缩略图
- 当前 winner 绿色边框 + ⭐ 标记
- 点击任意版本 → 画布节点预览切换为该版本
- 点击"选择" → 调用 `promote_version` → 切换 winner → 如果有下游节点，触发 Stale 检查
- 底部"再生成一个版本"按钮 → 以当前 Prompt 再次调用 `submit_generation`

**inputHash 机制**：

ArtifactVersion 记录 `inputHash`（上游依赖版本 + Prompt + 模型参数的哈希）。当上游变更时，通过 inputHash 判断当前版本是否还有效——如果上游没有实质变化（同样的 winner），可以跳过不必要的重新生成。

### 8.2 Stale 传播与影响分析

当上游节点发生实质变更（Prompt 修改、winner 切换、重新生成），其下游节点按 DAG 依赖关系传播标记为 Stale。

**传播规则**：

1. 节点 A 变更 → 遍历 `dependency` 类型的出边（不含 `reference` 和 `sequence`）
2. 对每个下游节点 B，比较 B.currentVersion.inputHash 与当前上游状态
3. 如果 inputHash 已失效 → B 标记为 Stale → 继续向 B 的下游传播
4. 如果 inputHash 仍有效（上游实际输出未变）→ 停止传播

**Stale 节点的用户交互**：

Stale 不自动触发重新生成。画布底部弹出影响分析条：

```
⚠ "产品主图" 变更影响 3 个节点 · 预计重新生成 ~2分钟 · 费用 ¥1.8
                                        [重新生成]  [暂不处理]
```

- **重新生成**：按拓扑序逐个重新生成所有 Stale 节点
- **暂不处理**：保留 Stale 标记，用户可以继续编辑其他内容，之后统一处理

这个设计允许用户做批量修改——先改脚本、换参考图、调 BGM，改完后一次性重新生成，而不是每改一个上游就触发一轮重算。

### 8.3 Gate 系统

Gate 是 Agent 在关键决策点暂停等待用户确认的机制。Gate 设置在**成本不可逆**的节点，借鉴 spark-video 的质量门禁思路。

**预设 Gate 点**：

| Gate | 触发时机 | 确认内容 |
|---|---|---|
| 分镜确认 | Agent 完成分镜规划后，开始生成前 | 分镜数量、内容、时长分配 |
| 成片预览 | 所有镜头生成完毕，拼接完成后 | 整体效果、节奏、转场 |

**Gate 交互**：

1. Agent 调用 `request_gate` → 对话面板展示确认卡片
2. 画布顶部 Agent 状态栏显示"等待确认..."
3. 用户选择：✅ 确认继续 / 💬 对话修改 / 🖱 直接编辑画布
4. Agent 收到确认后继续执行

**为什么只有 2 个 Gate 而非每步都确认**：

- 分镜确认前，Agent 只做了规划（创建节点和连线），零成本可撤回
- 分镜确认后到成片预览之间是生成和评审过程，这些是有成本的操作
- 用户可以在生成过程中随时干预（UserEditing），不需要额外的 Gate
- 过多 Gate 会让 Agent 模式退化成"每步都要点确认"的表单流程，失去自动化价值

### 8.4 转场配置

转场是 sequence 类型 MediaEdge 的属性，不是独立节点。

**支持的转场类型**：

| type | 说明 | 默认时长 |
|---|---|---|
| `cut` | 硬切，无过渡效果 | 0s |
| `crossfade` | 交叉淡入淡出 | 0.5s |
| `dissolve` | 溶解过渡 | 1.0s |
| `wipe` | 擦除过渡 | 0.5s |

**配置入口**：

- **画布上**：点击 sequence 连线上的转场标签 → 弹出浮层（转场类型下拉 + 时长输入）
- **属性面板**：选中 sequence 连线 → 右侧面板展示完整转场配置
- **Agent 自动**：Agent 根据镜头内容语义选择转场类型（情绪转换 → dissolve，节奏紧凑 → cut，时空跳转 → wipe）

**转场与拼接的关系**：

转场参数在最终拼接阶段由 Stitch Skill 读取并执行。修改转场参数不会让镜头节点 Stale（转场不影响单镜头内容），但会让成片节点 Stale（需要重新拼接）。

### 8.5 增量重算

基于 DAG 依赖分析，只重新生成受影响的节点，避免全量重算。

**重算策略**：

1. 用户修改节点 A → `mark_stale` 遍历 A 的下游 dependency 子图
2. 收集所有 Stale 节点，按拓扑序排序
3. 用户确认重新生成 → 按拓扑序逐个调用 `submit_generation`
4. 每个节点生成前检查 inputHash：如果上游 winner 实际未变（比如重新生成后产物相同），跳过该节点
5. 生成完成后更新 inputHash，如果下游的 inputHash 仍有效则停止继续传播

**成本预估**：

在用户确认重新生成前，系统预估并展示：

- 受影响节点数量
- 预估耗时（基于历史生成时长）
- 预估费用（基于模型定价 × 预估调用次数）

## 9. 后端 Skill 架构

### 9.1 设计理念

借鉴 spark-video 的角色分工思路，将 Agent 的能力拆分为独立的 Skill（技能角色）。每个 Skill 有明确的职责边界、输入输出契约和质量标准。

**为什么用 Skill 而不是单一 Agent**：

- 单一 Agent 提示词过长，能力退化
- Skill 独立部署，可以针对性优化（不同 Skill 可用不同模型）
- 失败隔离：某个 Skill 出错不影响其他 Skill 的结果
- 可复用：同一个 Skill 可以在不同工作流中复用

### 9.2 Skill 角色列表

| Skill | 职责 | 输入 | 输出 | 调用的命令 |
|---|---|---|---|---|
| **Producer** | 解析用户需求，生成 Brief，协调整体流程 | 用户自然语言 + 上传素材 | 结构化 Brief（目标平台、时长、风格、卖点） | — |
| **Screenwriter** | 基于 Brief 生成脚本和分镜表 | Brief | 分镜列表（每镜头的描述、时长、画面要求） | `create_media_node`（批量创建分镜节点） |
| **Director** | 为每个分镜生成具体的生成 Prompt | 分镜描述 + 素材引用 | 模型 Prompt + 参数配置 | `update_media_node`、`create_media_edge` |
| **Art Asset** | 管理和生成参考素材（角色一致性参考、风格参考等） | 分镜需求 + 已有素材 | 参考图/参考视频资产 | `create_media_node`、`submit_generation` |
| **Prompt Rewrite** | 当生成评审不通过时，分析原因并改写 Prompt 重试 | 失败原因 + 原 Prompt + 评审反馈 | 改写后的 Prompt | `update_media_node`、`submit_generation` |
| **Preflight Review** | 生成前检查：Prompt 质量、依赖完整性、参数合理性 | 节点状态 + 上游依赖 | pass/fail + 问题列表 | — |
| **Clip Review** | 生成后评审：画面质量、角色一致性、内容合规性 | 生成产物 + 分镜要求 | 分数 + 维度评价 + verdict | 写入 ReviewRecord |
| **Stitch** | 按 sequence 顺序拼接所有 winner 镜头，应用转场、BGM、字幕 | 所有 winner 视频 + sequence edges + 转场配置 | 成片视频 | `create_media_node`（成片节点）、`submit_generation` |

### 9.3 Skill 编排流程

Producer 作为顶层协调者，按以下流程编排其他 Skill：

```
用户输入
  │
  ▼
Producer（解析需求 → Brief）
  │
  ▼
Screenwriter（Brief → 分镜列表）──→ 画布出现分镜卡片
  │
  ▼
Gate: 分镜确认
  │
  ▼
Art Asset（生成/收集参考素材）──→ 画布出现素材节点 + 连线
  │
  ├──→ Director（分镜01 → Prompt）──→ Preflight Review ──→ submit_generation
  ├──→ Director（分镜02 → Prompt）──→ Preflight Review ──→ submit_generation
  ├──→ Director（分镜03 → Prompt）──→ Preflight Review ──→ submit_generation
  │         ...（按依赖拓扑序，可并行无依赖的分镜）
  │
  ▼
Clip Review（逐个评审）
  │── 通过 → promote_version
  │── 不通过 → Prompt Rewrite → 重试（最多 3 次）
  │── 3 次都不通过 → 请求用户帮助
  │
  ▼
所有镜头有 winner
  │
  ▼
Stitch（拼接成片）
  │
  ▼
Gate: 成片预览
  │
  ▼
导出
```

### 9.4 Skill 与命令 API 的关系

Skill 不直接操作数据库或画布。每个 Skill 的输出通过调用第 4 章定义的共享命令 API 落地。这保证了：

- Agent 的每一步操作都有审计记录（AgentStep）
- 画布通过事件流自动更新，Skill 无需关心前端渲染
- 用户手动操作和 Agent 操作走同一条数据通路，状态一致性有保障

### 9.5 Skill 的模型选择策略

不同 Skill 对模型能力的要求不同，可以使用不同的 LLM：

| Skill | 推荐模型能力 | 理由 |
|---|---|---|
| Producer | 强推理 | 需要理解复杂需求、做全局规划 |
| Screenwriter | 强创意 + 结构化输出 | 需要生成有创意且格式规范的分镜表 |
| Director | 领域知识 | 需要了解各生成模型的 Prompt 最佳实践 |
| Prompt Rewrite | 领域知识 + 推理 | 需要分析失败原因并改写 |
| Clip Review | 多模态理解 | 需要"看"生成的图片/视频并评判质量 |
| Stitch | 工具调用 | 主要是编排 FFmpeg 等工具，逻辑简单 |

具体模型映射在实现阶段根据可用模型和成本确定，此处只定义能力需求。
