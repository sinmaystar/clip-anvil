# M2a Studio Canvas React Flow Polish 设计与工作项

**状态**：待评审
**日期**：2026-06-17
**阶段目标**：让 Studio 画布先成为手动可用的专业编辑器，再进入生成任务、分镜工作流或 Agent 模式。

## 1. 背景

当前 Studio M1.x 已具备画布编辑器的核心基础：

- 文本、图片、视频、音频四类媒体节点。
- dependency 连线和后端 DAG 环检测。
- MediaGroup 分组、左侧资源树、右侧属性面板。
- 拖拽上传资产、MinIO 存储、Dagre 自动布局。
- `/ws/canvas` 事件通道。

但当前能力仍偏“功能打通”，还没有达到专业编辑器的日常可用体验：

- 分组只能完成基础创建和展示，资源组织能力不够完整。
- 连线文档仍保留 reference、sequence、transition 等复杂语义，且部分文档仍描述旧的 React Flow custom dependency edge 投影，和下一阶段产品决策及当前 SVG 动效连线实现不一致。
- 右侧属性面板视觉粗糙，信息密度、编辑能力和不同媒体类型的专属信息都不足。
- 资源树能展示基础列表，但还不能承担复杂项目的主导航职责。

本阶段聚焦 Studio 手动编辑体验，不引入 Agent、生成任务或分镜自动化。

### 1.1 当前实现校准

截至 2026-06-17，当前实现状态如下：

已具备：

- dependency edge 的 REST API 默认行为、DAG 环检测、重复边校验和删除接口。
- 连线创建采用从输出端口拖拽到任意目标 Node 的方式。
- 连线使用 SVG overlay 渲染曲线、流动动效和箭头，不再依赖 React Flow custom dependency edge 作为用户可见连线。
- 连线可直接选中并用 Delete / Backspace 删除。
- 成环失败已经使用画布级 toast 提示，文案解释“这条线会形成循环”。
- 分组后端 API 已支持创建、重命名、删除、替换成员；节点 API 已支持更新 `group_id`。
- `/ws/canvas` 已广播节点、连线和分组事件，前端断线重连后重新拉取画布。

仍需完成：

- 现行设计文档需要收敛到 Studio 用户只暴露 dependency。
- 属性面板仍以只读信息展示为主，需要改成编辑入口。
- 分组成员管理、分组重命名、节点加入/移出分组尚未在前端形成完整闭环。
- 资源树缺少成员数量、分组搜索、画布定位和更清晰的多节点扫描体验。
- 选中连线后还没有属性面板详情；节点属性面板只展示上游输入，没有展示下游依赖。
- 媒体 asset 的 mime、size、duration、metadata 已在后端部分保存，但 canvas payload 当前只暴露节点缩略图；M2a 需要决定是否扩展 payload 或先显示占位。

## 2. 已确认产品决策

### 2.1 画布先成为专业 Studio 编辑器

下一阶段优先解决用户手动组织、查找、编辑、连线和整理媒体资源的问题。

本阶段不追求 Agent 自动生产，也不做分镜工作流。画布先要能支撑一个包含较多素材和节点的真实项目。

### 2.2 连线只暴露 dependency

用户可见的连线语义只保留 dependency。

dependency 表示：

> 目标媒体资源依赖源媒体资源。

示例：

- 产品图 -> 视频节点：视频依赖产品图作为输入素材。
- 文案 -> 旁白音频：音频依赖文案生成。
- 音频 -> 成片视频：视频依赖音频作为配乐或旁白。

reference、sequence、transition 暂不作为 Studio 用户功能暴露。原因是多种连线语义会增加用户理解成本，而 dependency 已足够描述当前媒体资源之间的依赖关系。

数据库中的 `edge_type` 可以暂时保留兼容和未来扩展，但当前产品文档、前端 UI、API 默认行为和验收口径都应以 dependency 为唯一用户连线语义。

### 2.3 属性面板必须重做

属性面板是 Studio 的主要编辑入口，不能只是字段展示。

本阶段需要重做视觉、信息结构和编辑能力，并针对 text/image/video/audio 展示不同的媒体专属信息。

### 2.4 分组与资源组织是本阶段核心

分组是纯组织工具，不影响 dependency 关系，不影响生成逻辑。删除分组不删除节点，只解除组织关系。

本阶段应让用户可以用分组管理复杂画布，而不是只完成“新建一个分组”的最小功能。

## 3. 范围

### 3.1 包含

- 当前设计文档口径收敛：只启用 dependency 连线语义。
- 分组与资源组织增强。
- 左侧资源树体验优化。
- 右侧属性面板重做。
- dependency 连线体验打磨。
- 基础画布编辑体验补强。

### 3.2 不包含

- Agent 模式。
- 对话面板。
- 分镜工作流。
- reference 连线。
- sequence 连线。
- transition 配置。
- 生成任务。
- 版本列表。
- 自动评审。
- 模型供应商调用。
- 成片拼接或导出。

## 4. 工作项

### 4.1 文档口径收敛：只保留 dependency 连线语义

交付物：

- 更新 `docs/design/overview.md`。
- 更新 `docs/design/canvas.md`。
- 更新 `docs/design/studio-mode.md`。
- 更新 `docs/engineering/database.md` 中面向当前产品能力的连线说明。

具体要求：

- 删除或降级 reference、sequence、transition 作为下一阶段 Studio 用户能力的描述。
- 明确当前用户可见连线只有 dependency。
- 明确 `edge_type` 保留是数据兼容和未来扩展，不代表当前 UI 暴露多语义连线。
- Agent 模式文档中如果仍需要生产级 sequence 概念，应说明它不是本阶段 Studio 用户操作范围。

验收标准：

- 现行设计文档不再互相矛盾。
- Studio 下一阶段范围中不再出现 reference、sequence、transition 的用户交互要求。
- dependency 的语义在整体设计、画布设计和 Studio 设计中表述一致。

### 4.2 分组与资源组织增强

交付物：

- 支持多选节点创建分组。
- 支持分组重命名。
- 支持删除分组，并保留内部节点。
- 支持节点加入分组。
- 支持节点移出分组。
- 支持在属性面板中管理分组成员。
- 支持资源树中清楚展示分组、未分组和成员数量。
- 优化画布分组容器的视觉表现。

实现说明：

- 后端已有 `POST /api/groups`、`PATCH /api/groups/:id`、`DELETE /api/groups/:id`、`PUT /api/groups/:id/nodes`。
- 前端已有 `updateMediaGroup`、`deleteMediaGroup`、`replaceMediaGroupNodes` 和 `updateMediaNode(group_id)` API helper。
- M2a 的主要工作是前端交互闭环、状态派生和视觉质量，不应重复建设后端接口。

建议最小闭环：

- 选中多个节点后创建分组。
- 创建后自动选中分组，并在右侧属性面板展示分组详情。
- 分组属性面板可以修改名称、查看成员、移出成员、删除分组。
- 节点属性面板可以修改所属分组或移出分组。

行为规则：

- 一个节点最多属于一个分组。
- 分组不支持嵌套。
- 分组不影响 dependency 连线。
- 删除分组不删除节点。
- 空分组允许存在，但需要有明确空状态。

验收标准：

- 用户可以用分组管理一个包含 20 个以上节点的项目。
- 分组增删改后，画布、资源树、属性面板保持一致。
- 删除分组后，节点仍保留在画布，并回到未分组区域。
- 分组操作不会删除或改变 dependency 连线。

### 4.3 资源树体验优化

交付物：

- 优化资源树视觉层级和密度。
- 分组标题显示成员数量。
- 节点行展示媒体类型、标题、状态和缩略信息。
- 搜索和类型筛选继续可用。
- 点击节点后画布定位并选中节点。
- 点击分组后画布定位到分组区域。
- 未分组区域更清楚。
- 搜索结果仍能看清节点所属分组。

设计要求：

- 资源树是 Workspace 内媒体资源的主索引。
- 搜索优先匹配节点标题，必要时也可匹配分组名称。
- 类型筛选只过滤节点，不应让用户误以为分组被删除。
- 折叠分组只影响左侧资源树，不影响画布分组容器。
- 点击节点时，画布应平滑定位到该节点并选中，默认保留当前 zoom。
- 点击分组时，画布应定位到分组 bounds；如果分组为空，则定位到分组容器中心。

验收标准：

- 用户可以只通过左侧资源树快速找到资源。
- 选中资源后，画布和属性面板同步。
- 资源树在节点数量较多时仍保持可扫描。

### 4.4 属性面板重做

交付物：

- 重做右侧属性面板视觉。
- 支持编辑节点标题。
- 支持编辑节点 Prompt。
- 支持查看和修改节点所属分组。
- 支持查看上游依赖。
- 支持查看下游依赖。
- 支持删除节点。
- 支持编辑分组名称。
- 支持管理分组成员。
- 支持删除分组。
- 优化空状态。

媒体类型专属信息：

| 类型 | 专属信息 |
|---|---|
| text | Prompt、正文摘要、字数 |
| image | 缩略图、文件类型、文件大小、尺寸占位 |
| video | 缩略图、文件类型、文件大小、时长占位、分辨率占位 |
| audio | 文件类型、文件大小、时长占位 |

说明：

- 当前后端若没有真实尺寸、时长或分辨率字段，前端可先显示占位状态，但 UI 结构要为后续元数据接入留好位置。
- M2a 先不新增生成/元数据解析任务；媒体专属信息优先使用当前 canvas node 的 `thumbnail_url`、`asset_id`、asset summary 或占位状态。
- 若需要展示文件类型和文件大小，应优先扩展 canvas payload 中的节点 asset summary，而不是让属性面板为每个节点额外发起资产查询。
- 危险操作要有明确视觉区分，避免误删节点或分组。
- 属性面板要服务高频编辑，避免只读信息堆叠。

验收标准：

- 选中不同媒体类型节点时，属性面板展示的信息不同。
- 用户可以在属性面板完成常见编辑，而不是必须回到节点卡片。
- 视觉质量达到专业编辑器标准：清晰、紧凑、层级明确。

### 4.5 dependency 连线体验打磨

交付物：

- 保留单一 dependency 连线。
- 保留现有拖拽创建入口、SVG 动效连线和画布级错误提示。
- 选中连线后，属性面板展示依赖关系。
- 支持删除 dependency 连线。
- 节点属性面板展示“依赖于”和“被依赖于”两类关系。

行为规则：

- A -> B 表示 B 依赖 A。
- 禁止自连接。
- 禁止 dependency 成环。
- 删除节点时，相关 dependency 连线应同步清理。

验收标准：

- 用户能清楚理解连线方向和依赖含义。
- 连线错误提示能说明问题，而不是只显示通用失败。
- dependency 关系能在画布、属性面板和资源树语境中保持一致。

实现说明：

- M2a 不再恢复 React Flow custom dependency edge 作为可见连线。旧 custom dependency edge 只作为历史兼容清理对象。
- 上游/下游依赖优先由 `CanvasPayload.edges + nodes` 在前端派生，避免新增 `/nodes/:id/outputs` 接口。

### 4.6 画布编辑基础体验补强

交付物：

- 多选状态优化。
- 选中节点、分组、连线的高亮规则统一。
- 右键菜单根据当前选中内容展示不同操作。
- 删除节点时同步删除相关连线。
- 自动布局继续可用，并适配分组。
- 空画布引导优化。
- 常见失败状态提供清楚反馈。

建议右键菜单：

| 场景 | 操作 |
|---|---|
| 空白画布 | 创建文本、创建图片、创建视频、创建音频 |
| 单选节点 | 删除节点、创建分组、开始依赖连线 |
| 多选节点 | 创建分组、删除节点 |
| 分组 | 重命名分组、删除分组 |
| 连线 | 删除依赖 |

验收标准：

- 创建、选择、移动、分组、连线、删除形成顺滑闭环。
- 常见操作能从画布和面板两处完成。
- 画布上不出现明显状态不同步。

## 5. 建议实施顺序

1. 文档口径收敛，统一 dependency-only 决策。
2. 建立前端画布派生数据层：选中节点、分组、连线，上游/下游依赖，分组成员，未分组节点。
3. 重构属性面板信息架构和基础视觉，先承载节点、分组和连线详情。
4. 补齐分组编辑闭环：多选建组、重命名、成员管理、删除保留节点。
5. 优化资源树导航、搜索、成员数量和画布定位。
6. 最后做右键菜单、多选、空画布、统一高亮等整体交互 polish 和回归验证。

这个顺序的原因是属性面板、资源树、连线详情和分组编辑都会复用同一套派生数据。先稳定 selection 和 selectors，可以减少后续状态不同步和重复计算。

## 6. 验收场景

### 6.1 复杂素材组织

用户创建或上传 20 个以上媒体节点，将它们分成多个分组。用户可以通过资源树搜索、筛选、定位节点，也可以在属性面板查看和调整分组成员。

通过条件：

- 分组和未分组节点清楚可见。
- 节点能加入和移出分组。
- 删除分组后节点仍保留。

### 6.2 手动依赖编辑

用户创建产品图、文案、音频和视频节点，用 dependency 表示生成依赖。

通过条件：

- A -> B 的含义清楚。
- 成环创建失败，并给出可理解提示。
- 选中节点可以看到上游和下游依赖。
- 选中连线可以删除依赖。

### 6.3 媒体属性查看与编辑

用户分别选中文本、图片、视频和音频节点。

通过条件：

- 属性面板展示不同媒体类型的专属信息。
- 标题和 Prompt 可编辑。
- 分组归属可调整。
- 删除操作有明确危险样式。

### 6.4 文档一致性

用户阅读当前设计文档时，能明确知道下一阶段 Studio 只启用 dependency 连线。

通过条件：

- 当前文档入口、Studio 设计、画布设计、数据库设计口径一致。
- reference、sequence、transition 不再作为 M2a 的交付要求。

## 8. 开放问题

1. 分组成员管理 M2a 先用属性面板选择和移出完成闭环；拖拽可作为后续增强。
2. 资源树中的节点移动到分组 M2a 先用菜单或属性面板完成；资源树拖拽不进入首轮闭环。
3. 图片、视频、音频的尺寸、时长、分辨率 M2a 先保留 UI 占位；文件类型和文件大小优先通过 canvas payload 的 asset summary 暴露。
4. 属性面板 M2a 使用单页分区结构，不引入 tab；如果后续生成任务/版本列表进入面板，再评估 tab。
