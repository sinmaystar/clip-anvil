# ClipAnvil Studio 模式设计方案

## 1. 定位

Studio 是用户主导的自由创作空间。用户可以像使用白板一样组织素材，也可以像使用节点编辑器一样把媒体资源连成生成流程。

画布完全可编辑，没有 Agent 运行，不存在并发冲突。

## 1.1 当前实现快照

当前代码已交付 Studio M1.x 的核心 DAG 编辑能力：

- 三栏布局：可折叠左侧资源树 + tldraw 画布 + 右侧属性面板。
- 左侧栏包含返回项目列表、项目标题、明亮/暗夜切换、搜索、分组资源树和未分组节点列表。
- 画布隐藏 tldraw 原生顶部工具栏、底部绘图工具和右侧样式面板。
- 右键画布空白处创建文本、图片、视频、音频节点；也支持拖拽文件上传后创建资产节点。
- 单击节点后在节点下方展示编辑面板，包含标题、引用占位、Prompt、模型选择；标题/Prompt 自动保存。
- 支持依赖连线、删除连线、节点输入查询、分组创建/删除、Dagre 自动整理。
- 删除节点、撤销恢复、拖拽位置、Camera 持久化已和后端同步。
- `/ws/canvas` 已用于节点、连线、分组事件广播；前端断线重连后重新拉取画布。
- 尚未落地：生成任务、版本列表、自动评审、Agent 模式、reference/sequence 的完整配置交互。

## 2. 界面布局（目标态）

```
┌──────────────────────────────────────────────────────────────┐
│  影砧  ·  ☕ 咖啡广告项目    [Studio 模式 ▾]     ⌘K  导出  设置 │
├──────────┬───────────────────────────────────┬───────────────┤
│          │    浮动工具栏                       │              │
│ 🔍搜索    │  [↖选择|📝文本|🖼图片|🎬视频|🔊音频]  │  ⚙ 节点属性  │
│          │                                   │              │
│[类型筛选] │                                   │ [选中节点时   │
│          │         画布区域                    │  展示属性面板] │
│ 📁 素材   │      （tldraw 无限画布）            │              │
│  🖼 ...   │                                   │ [未选中时     │
│ 📁 分镜   │    [媒体节点卡片]                   │  面板隐藏]    │
│  🎬 ...   │    [连线 / 箭头]                   │              │
│ 📁 音频   │    [分组容器]                      │              │
│  🔊 ...   │                                   │              │
│          │  [缩放] [自动整理]                   │              │
└──────────┴───────────────────────────────────┴───────────────┘
 ~200px            flex:1                     ~280px（可折叠）
```

三栏职责：

| 区域 | 职责 |
|---|---|
| **左侧资源树** | Workspace 内所有媒体资源的索引和组织 |
| **中间画布** | tldraw 无限画布，承载节点卡片、连线、分组 |
| **右侧属性面板** | 选中节点的详细属性编辑（未选中时隐藏） |

当前已有右侧属性面板和底部自动布局控件；顶部浮动工具栏、模型参数和版本系统仍未引入。

## 3. 左侧资源树（目标态）

一棵树 + 筛选，不搞多视图切换：

- **顶部搜索框**：按名称模糊搜索
- **类型筛选 chips**：全部 / 图片 / 视频 / 文本 / 音频，单选切换
- **树结构**：文件夹（MediaGroup）+ 资源（MediaNode），支持拖拽排序
- **状态徽标**：每个资源右侧显示状态图标（✓ 完成 / ⟳ 生成中 / ○ 草稿 / ⚠ 过期 / ✗ 失败）
- **底部折叠按钮**：收起侧栏获得更大画布空间
- **双向同步**：画布分组变更实时同步到资源树文件夹层级，反之亦然

## 4. 浮动工具栏（目标态）

画布顶部居中的浮动工具栏，提供快捷创建入口：

```
[ ↖选择 | 📝文本 | 🖼图片 | 🎬视频 | 🔊音频 | — | 📎上传 ]
```

选择工具类型后，在画布上点击即创建对应类型的 Draft 节点。

## 5. 创建资源

四种创建入口：

| 入口 | 操作 | 适用场景 |
|---|---|---|
| **右键菜单** | 画布空白处右键 → 选择类型 | 精确定位创建 |
| **浮动工具栏** | 选择工具类型 → 画布上点击 | 批量创建同类节点 |
| **拖拽上传** | 从系统文件管理器拖文件到画布 | 快速导入本地素材 |
| **左侧资源树** | 点击 + 按钮新建 | 先建资源，稍后拖到画布 |

创建后生成一个 Draft 状态的 MediaNode，画布上出现对应类型的占位卡片。

**数据流**：

```
用户点击创建
  → POST /api/nodes { nodeType, canvasX, canvasY }
  → 等后端返回（~200ms）
  → 成功 → editor.createShape(nodeToShape(response))
  → 失败 → toast "创建失败"
```

## 6. 编辑资源

### 6.1 双层编辑（目标态）

| 深度 | 交互方式 | 覆盖内容 |
|---|---|---|
| **轻量编辑** | 直接在节点卡片上操作 | 修改标题、编写 Prompt、选择模型、点击生成 |
| **深度编辑** | 单击节点 → 右侧属性面板 | 版本历史、模型参数、评审记录、高级选项、参考输入管理 |

### 6.2 节点卡片内联编辑

M1 当前的内联编辑不是嵌在节点卡片内部，而是单击节点后在节点下方渲染一个跟随画布移动的编辑面板。这样可以容纳更长 Prompt，也避免节点卡片本身被复杂表单撑大。

```
┌──────────────────────┐
│ 🎬 标题        [状态] │  ← 可双击编辑标题
├──────────────────────┤
│ [缩略图/预览/占位]    │  ← 内容区
├──────────────────────┤
│ 输入引用: @A @B       │  ← 上游依赖的缩略 chip
├──────────────────────┤
│ [Prompt 输入区域]     │  ← 可直接编写，支持 @引用
│ [模型选择 ▾] [▶生成]  │  ← 操作按钮
└──────────────────────┘
```

### 6.3 右侧属性面板

当前右侧属性面板已展示选中节点/分组的基础信息、Prompt 摘要、输入数量和分组信息，并支持删除分组。下面是版本/模型系统落地后的目标态扩展。

单击节点时右侧面板展开，包含：

- **基本信息**：标题、类型、状态、创建时间
- **Prompt 编辑器**：完整编辑区域，支持 @引用弹出资源选择器
- **模型配置**：供应商选择、模型选择、参数调节（分辨率、步数等）
- **输入引用**：列出所有上游依赖，可添加/删除
- **版本列表**：网格展示所有版本缩略图
  - 当前 winner 绿色边框 + ⭐
  - 点击版本 → 画布节点预览切换
  - 点击"选择" → promote_version → 切换 winner
  - "再生成一个版本"按钮
- **评审记录**：各维度评分、批评文本

## 7. 建立连线

三种连线方式：

| 方式 | 操作 | 结果 |
|---|---|---|
| **拖拽连线** | 从 A 输出端口拖到 B 输入端口 | 当前已落地：创建 dependency edge |
| **Prompt @引用** | 在 B 的 Prompt 中输入 `@` → 弹出资源选择器 → 选择 A | 目标态：创建 dependency edge + 在 Prompt 中插入引用标记 |
| **右键连线** | 选中两个节点 → 右键 → "建立依赖" / "建立序列" | 目标态：创建指定类型的 edge |

**数据流**：

```
用户拖拽连线
  → POST /api/edges { from_node_id, to_node_id }
  → 后端做 DAG 环检测
  → 成功 → editor.createShape(arrowShape) + binding
  → 失败（成环）→ toast "不能形成循环依赖"
```

连线创建后，B 的"输入引用"区域自动展示 A 的缩略图和标题。

## 8. 分组操作

- **创建分组**：选中多个节点 → 右键"创建分组" / ⌘G → 节点被包裹在虚线容器中
- **拖入/拖出**：目标态为直接拖拽节点进出分组容器；当前通过创建/替换分组成员关系落库
- **折叠分组**：目标态为点击分组标题栏折叠，只显示名称和成员计数
- **左侧同步**：分组变更实时同步到资源树文件夹

分组是纯组织工具，依赖连线可自由跨越分组边界。

## 9. 生成流程

1. 用户在节点卡片上编写 Prompt、选择模型
2. 点击 ▶ 生成 → `submit_generation` → 状态 Ready → Queued → Running
3. 进度通过 WebSocket 实时推送 → 卡片显示进度条
4. 生成完成 → 自动评审 → Succeeded（绿色）或 Failed（红色）
5. 用户可在属性面板查看版本列表、切换 winner、请求重新生成

## 10. 节点状态机

```
Draft → Ready → Queued → Running → Succeeded
  ↑       ↑                            │
  │   UserEditing                    Stale ◄── 上游变更传播
  │       │                            │
  └───── Ready                   Failed / Rejected
```

**UserEditing 状态**：
- 用户点击节点进入编辑状态 → 节点标记为 UserEditing
- 此状态下如果有后台 Agent 推送的更新（仅从 Agent 模式切换过来时可能存在），前端忽略该节点的 Agent 更新
- 用户编辑完毕保存 → 状态恢复

## 11. Stale 处理

上游节点变更后，Stale 不自动触发重新生成。画布底部弹出影响分析条：

```
⚠ "产品主图" 变更影响 3 个节点 · 预计重新生成 ~2分钟 · 费用 ¥1.8
                                        [重新生成]  [暂不处理]
```

- **重新生成**：按拓扑序逐个重新生成所有 Stale 节点
- **暂不处理**：保留 Stale 标记，用户可继续编辑，之后统一处理

这允许用户批量修改——先改脚本、换参考图、调 BGM，改完后一次性重新生成。

**成本预估**（重新生成前展示）：
- 受影响节点数量
- 预估耗时（基于历史生成时长）
- 预估费用（基于模型定价 × 预估调用次数）

## 12. 面板联动规则

| 场景 | 行为 |
|---|---|
| 未选中任何节点 | 右侧属性面板隐藏 |
| 单击选中一个节点 | 右侧展示属性面板 |
| 点击画布空白区域 | 取消选择，属性面板隐藏 |
| 左侧资源树点击某资源 | 画布定位到对应节点 + 右侧展示属性 |
| 选中连线 | 右侧展示连线详情（dependency/reference 显示基本信息，sequence 显示转场配置） |
